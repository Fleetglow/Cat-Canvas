# 节点对齐与整理工具条设计

## 目标

为 Cat Canvas 增加多节点布局工具：用户选中至少两个节点后，可在屏幕顶部居中的浮动工具条中执行边缘对齐、中心对齐、等距分布和按连接关系整理，并可通过快捷键执行六种对齐操作。

开发分支：`feature/node-layout-toolbar`

## 范围

- 多选时显示顶部布局工具条。
- 支持左、左右居中、右、上、上下居中、下对齐。
- 支持水平等距和垂直等距。
- 支持“整理选中”。
- 支持 `Alt+A/D/W/S/V/H` 快捷键。
- 支持抓手与选择两种画布交互模式，并记忆用户选择。
- 支持无修饰键 `H/V` 快捷切换抓手与选择模式。
- 日志中的图生图、发送到画布和再次运行从视口中心按垂直优先规则寻找空白落点。
- 所有布局操作接入现有撤销、渲染、连线刷新和自动保存流程。

不包含：吸附参考线、网格吸附、自动避让未选节点、整张画布一键整理、快捷键自定义。

## 工具条交互

工具条固定在画布可视区域顶部居中，不随画布缩放或平移。仅在当前画布存在且 `selected.size >= 2` 时显示；单选、无选中或离开画布时隐藏。

按钮从左到右分组如下：

1. 左对齐
2. 左右居中
3. 右对齐
4. 上对齐
5. 上下居中
6. 下对齐
7. 水平等距
8. 垂直等距
9. 整理选中

对齐、等距、整理之间使用视觉分隔。九个操作使用 `static/images/layout/` 下的自定义 SVG 图标，通过 CSS mask 继承亮色、暗色和悬停状态颜色；“整理选中”按钮同时显示图标和文字。所有按钮提供中文 `title` 与 `aria-label`。等距操作至少需要三个可布局单元；归一化后只有两个布局单元时，两个等距按钮不可见。

工具条自身的鼠标事件必须阻止冒泡，避免触发画布取消选择或平移。

## 布局单元与尺寸

布局计算使用节点在当前 DOM 中的实际宽高；DOM 不可用时回退到节点保存的 `w/h` 或默认尺寸。

普通节点是独立布局单元。`group` 和 `promptGroup` 是原子布局单元：

- 选中分组成员时，将该成员提升为所属分组参与布局。
- 同一分组及其成员不会重复参与计算。
- 移动分组时，按相同位移递归移动其成员。
- 坐标最终取整，避免保存小数漂移。

## 对齐规则

所有操作只改变需要改变的坐标轴，另一轴保持不变。

- 左对齐：所有布局单元左边缘对齐到选区最左边缘。
- 右对齐：所有布局单元右边缘对齐到选区最右边缘。
- 上对齐：所有布局单元上边缘对齐到选区最上边缘。
- 下对齐：所有布局单元下边缘对齐到选区最下边缘。
- 左右居中：所有布局单元只左右移动，X 中心对齐到选区水平中心线。
- 上下居中：所有布局单元只上下移动，Y 中心对齐到选区垂直中心线。

选区中心和边缘均根据参与布局单元的联合边界计算。

## 等距规则

等距分布按照节点边界之间的空白间隙计算，而不是平均中心点距离。

- 水平等距：按左边缘排序，固定最左和最右布局单元的位置，在两者之间平均分配水平空隙，只修改 X。
- 垂直等距：按上边缘排序，固定最上和最下布局单元的位置，在两者之间平均分配垂直空隙，只修改 Y。
- 排序相同时以节点 ID 保证结果稳定。
- 若当前跨度不足以容纳所有节点，允许计算出负间隙，使结果保持确定性；不自动缩放节点。

## 整理选中规则

整理逻辑移植自 `D:/AI/Infinite-Canvas` 的普通画布实现，但仅处理当前明确选中的多个布局单元，不扩展到未选中的连接节点。

1. 保留当前选区联合边界的最左上角作为布局起点。
2. 仅使用选中布局单元之间的内部连接。
3. 根据有向连接的入度和传播深度计算层级。
4. 同一深度的节点放在同一列，列从左到右排列。
5. 列内按整理前的 Y 坐标排序，保持用户已有的上下顺序。
6. 垂直间距为节点高度加 `56px`。
7. 水平间距为当前列最大宽度加 `180px`。
8. 环形或无法从根节点覆盖的节点保持确定性回退层级，不阻塞整理操作。
9. 不移动任何未选节点，也不主动避让未选节点。

## 快捷键

画布已打开、焦点不在可编辑控件且没有弹窗交互时，`Ctrl+A` 使用输入法无关的 `KeyboardEvent.code === 'KeyA'` 选中当前画布全部节点并刷新选择状态。

仅当至少选中两个节点时，以下布局快捷键响应：

- `Alt+A`：左对齐
- `Alt+D`：右对齐
- `Alt+W`：上对齐
- `Alt+S`：下对齐
- `Alt+V`：上下居中，节点只上下移动，Y 中心相同
- `Alt+H`：左右居中，节点只左右移动，X 中心相同

事件在捕获阶段识别，使用不受中英文输入法字符影响的 `KeyboardEvent.code` 匹配物理按键；匹配后调用 `preventDefault()` 和 `stopPropagation()`。部分浏览器可能保留 `Alt+D` 用于聚焦地址栏；页面端只能尽力拦截，不增加备用快捷键。

快捷键在 `input`、`textarea`、`select`、`option`、`contenteditable` 和现有可编辑节点控件中不触发。除可编辑控件外，不依赖 `event.key` 或当前输入法状态，保证不同输入法下行为一致。

## 抓手与选择模式

右下角 `zoom-control` 在地图按钮左侧增加一个模式切换按钮。按钮只显示图标：抓手模式使用 `icon_抓手.svg`，选择模式使用 `icon_选择.svg`；图标复制到项目静态资源目录并通过 CSS mask 继承主题与悬停颜色。

模式状态使用 `localStorage` 保存，所有画布共用；首次使用或保存值无效时默认为抓手模式。按钮图标表示当前模式，`title` 与 `aria-label` 表示当前模式及可执行的切换操作。

快捷键使用物理键码且仅在无修饰键、非编辑状态和无弹窗交互时响应：

- `H`：切换到抓手模式。
- `V`：切换到选择模式。

无修饰键要求确保它们不与 `Alt+H/V` 布局快捷键冲突。

事件优先级如下：

1. 空格按住时强制临时平移，两种模式一致。
2. 鼠标中键始终平移，两种模式一致。
3. Shift/Ctrl 切割模式沿用现有配置并保持优先。
4. 抓手模式下，空白处左键拖动平移；现有多选修饰键仍可启动框选。
5. 选择模式下，空白处左键直接启动框选；零面积点击清空选择。
6. 节点点击、节点拖动、端口连线、右键菜单和双击添加节点行为不因模式改变。

抓手模式保持画布 `grab/grabbing` 光标；选择模式使用默认箭头，框选过程中继续使用现有框选状态样式。切换模式不修改画布数据、不产生撤销记录，也不触发画布保存。

## 日志创建节点落点

日志中的“图生图”“发送到画布”“再次运行”以及它们共享的输出创建链路统一使用 `findEmptyPoint(w, h)` 搜索落点，不再放到全画布最右侧。

搜索以当前可视世界区域中心为基础：

- `startX = viewCenterX - w / 2`
- `startY = viewCenterY - h / 2`
- 间隙固定为 `40px`
- 每列最多探测 `20` 个候选位置

搜索顺序垂直优先。第 `row` 个候选位置为：

- `x = startX + column × (w + 40)`
- `y = startY + row × (h + 40)`

每列依次检查 `row = 0..19`。若全部与现有节点碰撞，则 `column += 1`，移动到右侧一列，并从 `startY` 重新向下检查。列数不设固定限制，直到找到空位；有限节点和有限尺寸保证最终可在右侧找到候选位置。

碰撞检测使用现有节点的实际 DOM 尺寸，DOM 不可用时回退到保存尺寸或默认尺寸。候选矩形与现有节点边界之间必须保留至少 `40px`，边界间距恰好为 `40px` 时视为不碰撞。空画布直接返回视口中心候选位置。

各入口的占位范围：

- 发送到画布：使用新图片节点的实际宽高，并按 CSS 最小尺寸 `220×96` 兜底。
- 图生图：使用提示词、图片和生成器组成的完整链路 footprint。
- 再次运行：主节点、提示词节点和最多八个参考图节点作为一个整体 footprint 搜索。存在提示词或参考图时，左列宽度偏移沿用现有 `340px`；提示词按 `310×180` 估算，参考图按 `260×336` 估算并沿用 `y = 110 + i × 86` 的现有排列。整体宽度为 `340 + mainW`，整体高度为主节点高度与左列最下边界的较大值。找到整体左上角后，主节点 X 加 `340px`，其余节点继续使用相对主节点的现有坐标。没有提示词和参考图时直接使用主节点 footprint。

新落点只改变初始创建坐标。创建后的节点选中、视口聚焦、缩放到 `100%`、撤销、连接和自动保存行为保持现状。

## 代码结构

改动保持在现有画布文件中，不增加依赖：

- `static/canvas.html`：维护顶部布局工具条，并在右下角缩放控件中增加模式按钮。
- `static/css/canvas.css`：维护布局工具条样式，增加模式按钮、模式光标和图标 mask 样式。
- `static/js/canvas.js`：维护布局命令和交互模式；更新 `findEmptyPoint()` 为空白搜索，并让再次运行按整组 footprint 换算坐标。
- `static/js/i18n/canvas.js`：增加工具条和模式按钮文案与提示。
- `static/images/layout/`：保存布局与抓手/选择模式自定义 SVG 图标。

所有布局按钮与 `Alt` 快捷键共用布局命令入口；模式按钮与 `H/V` 快捷键共用模式切换入口，避免同一功能出现两套状态。

## 数据流

一次有效布局操作按以下顺序执行：

1. 检查画布、选中数量和操作所需最小节点数。
2. 将选中 ID 归一化为不重复的原子布局单元。
3. 在修改坐标前调用一次 `pushUndo()`。
4. 计算并写回节点坐标；分组成员同步平移。
5. 调用 `render()` 更新节点、连线、选中态和小地图。
6. 调用 `scheduleSave()` 保存画布。

无有效坐标变化时不压入撤销记录、不渲染、不保存。

## 异常与边界

- 选中 ID 对应节点已不存在时忽略该 ID。
- 归一化后不足两个布局单元时不执行。
- 等距归一化后不足三个布局单元时不执行。
- 节点尺寸不同仍按真实边界正确对齐。
- 分组嵌套通过 `seen` 集合避免重复移动或递归循环。
- 操作后保持原有 `selected` 集合，不改变用户选择。
- 布局不修改节点尺寸、连接关系、分组成员关系或视口。

## 验收标准

- 单选或无选中时工具条不显示；选中至少两个节点后显示在屏幕顶部居中。
- 九个按钮顺序符合本设计：六种对齐、两种等距、整理选中；整理按钮位于最后。
- 六种对齐在不同尺寸节点上按真实边界工作。
- 水平和垂直等距固定两端并平均边界间隙；只有两个布局单元时等距按钮不可见。
- 整理按连接深度从左到右排列，未选节点不移动。
- 分组参与布局时成员保持相对位置并同步移动。
- 六个快捷键使用物理键码，与对应按钮结果一致，在任意输入法下可用，编辑文本时不触发。
- 每次有效操作可一次撤销，并触发自动保存。
- 工具条操作不会取消选择、平移画布或触发节点拖动。
- 右下角模式按钮显示当前抓手/选择图标，点击后立即切换并持久化。
- 抓手模式保持当前左键平移行为；选择模式的空白左键执行点击清空或拖动框选。
- 两种模式下空格和中键都能临时平移，切割、节点拖动、连线和右键行为保持不变。
- 无修饰键 `H/V` 在不同输入法下切换模式，不影响 `Alt+H/V` 布局快捷键。
- 三个日志创建入口都从当前视口中心开始，按每列 20 次、垂直优先、右向换列规则找到空位。
- 新建 footprint 与现有节点保持至少 `40px`，再次运行的提示词和参考图不会与旧节点重叠。
